# Functions

Script càng lớn thì cấu trúc càng dễ trở nên rối rắm. Nếu chúng ta phải sử dụng cùng một chuỗi tác vụ lặp đi lặp lại nhiều lần, kích thước của script cũng sẽ phình to tương ứng. Trong những trường hợp như vậy, hàm (functions) là giải pháp giúp tối ưu đồng thời cả dung lượng lẫn độ rõ ràng cho mã nguồn. Với hàm, chúng ta gộp nhiều câu lệnh vào trong một khối đặt giữa cặp dấu ngoặc nhọn (`{ ... }`) và gọi chúng thông qua một tên hàm do chính mình định nghĩa. Khi một hàm đã được khai báo, nó có thể được gọi và tái sử dụng ở bất kỳ đâu trong suốt quá trình chạy script.

Hàm là một thành phần thiết yếu trong các script và chương trình, dùng để thực thi các câu lệnh lặp lại với những giá trị và giai đoạn khác nhau. Nhờ đó, chúng ta không cần viết lặp lại toàn bộ đoạn mã nhiều lần mà chỉ cần tạo một hàm duy nhất đảm nhận các lệnh cụ thể đó. Việc định nghĩa hàm giúp mã nguồn dễ đọc hơn và giữ cho script gọn gàng nhất có thể. Một quy tắc quan trọng cần lưu ý là hàm luôn phải được định nghĩa trước lần gọi đầu tiên, vì script được trình thông dịch xử lý tuần tự từ trên xuống dưới. Do đó, phần khai báo hàm thường được đặt ở đầu script. Có hai cách để định nghĩa hàm trong Bash:

#### Cách 1 - Khai báo hàm (Method 1 - Functions)

```bash
function name {
    <commands>
}
```

#### Cách 2 - Khai báo hàm (Method 2 - Functions)

```bash
name() {
    <commands>
}
```

Chúng ta có thể chọn cách khai báo hàm nào thuận tiện nhất với mình. Trong script `CIDR.sh`, chúng ta sử dụng cách thứ nhất vì từ khóa `function` giúp mã nguồn dễ đọc và dễ nhận diện hơn:

#### CIDR.sh

```bash
<SNIP>
# Identify Network range for the specified IP address(es)
function network_range {
    for ip in $ipaddr
    do
        netrange=$(whois $ip | grep "NetRange\|CIDR" | tee -a CIDR.txt)
        cidr=$(whois $ip | grep "CIDR" | awk '{print $2}')
        cidr_ips=$(prips $cidr)
        echo -e "\nNetRange for $ip:"
        echo -e "$netrange"
    done
}
<SNIP>
```

Để chạy một hàm, chúng ta chỉ cần gọi đúng tên hàm đã khai báo như cách đã thấy trong cấu trúc `case`:

#### Thực thi hàm - CIDR.sh (Function Execution - CIDR.sh)

```bash
<SNIP>
case $opt in
    "1") network_range ;;
    "2") ping_host ;;
    "3") network_range && ping_host ;;
    "*") exit 0 ;;
esac
```

## Parameter Passing

Các hàm nên được thiết kế sao cho có thể xử lý dữ liệu theo một cấu trúc cố định hoặc ít nhất là tuân theo một định dạng nhất định. Như trong script `CIDR.sh`, hàm `network_range` làm việc với định dạng địa chỉ IP. Việc truyền tham số là tùy chọn nên chúng ta hoàn toàn có thể gọi hàm mà không cần truyền tham số nào. Về nguyên tắc, tham số truyền vào hàm hoạt động tương tự như đối số truyền vào một shell script: sử dụng `$1` - `$9` (`${n}`) hoặc `$variable`. Mỗi hàm sở hữu một bộ tham số vị trí độc lập nên chúng không bị xung đột với tham số của các hàm khác hay đối số dòng lệnh của script chính.

Một điểm khác biệt quan trọng giữa Bash script và nhiều ngôn ngữ lập trình khác là mọi biến được định nghĩa đều mặc định mang phạm vi toàn cục (global), trừ khi được khai báo tường minh bằng từ khóa [`local`](https://www.tldp.org/LDP/abs/html/localvar.html). Điều này có nghĩa là ngay khi một biến được khởi tạo bên trong hàm, chúng ta vẫn có thể gọi và sử dụng biến đó ở phần script chính bên ngoài hàm. Cách truyền tham số vào hàm cũng tương tự như truyền đối số cho script:

#### PrintPars.sh

```bash
#!/bin/bash

function print_pars {
    echo $1 $2 $3
}

one="First parameter"
two="Second parameter"
three="Third parameter"

print_pars "$one" "$two" "$three"
```

```shellsession
phat2007dhsp@htb[/htb]$ ./PrintPars.sh
First parameter Second parameter Third parameter
```

## Return Values

Khi chúng ta khởi chạy một tiến trình mới, mỗi tiến trình con (chẳng hạn như một hàm trong script đang chạy) sẽ gửi một mã trả về (return code) về cho tiến trình cha (Bash shell dùng để chạy script) ngay khi kết thúc nhằm thông báo trạng thái thực thi. Thông tin này giúp xác định xem tiến trình đã chạy thành công hay gặp phải lỗi cụ thể nào, từ đó tiến trình cha có thể quyết định luồng xử lý tiếp theo của chương trình.

| Mã trả về (Return Code) | Mô tả (Description) |
| :---: | :--- |
| `1` | Lỗi chung (General errors) |
| `2` | Sử dụng sai lệnh tích hợp của shell (Misuse of shell builtins) |
| `126` | Lệnh được gọi không thể thực thi (Command invoked cannot execute) |
| `127` | Không tìm thấy lệnh (Command not found) |
| `128` | Đối số không hợp lệ cho lệnh `exit` (Invalid argument to exit) |
| `128+n` | Tín hiệu lỗi nghiêm trọng `n` (Fatal error signal "n") |
| `130` | Script bị ngắt bởi tổ hợp phím `Ctrl+C` (Script terminated by Control-C) |
| `255*` | Mã trạng thái thoát vượt quá phạm vi cho phép (Exit status out of range) |

Để lấy lại giá trị từ một hàm, chúng ta có thể sử dụng nhiều cách như `return`, `echo` hoặc gán qua biến. Trong ví dụ sau, chúng ta sẽ xem cách dùng `$?` để đọc mã trả về, cách truyền đối số vào hàm và cách lưu kết quả đầu ra của hàm vào một biến:

#### Return.sh

```bash
#!/bin/bash

function given_args {
    if [ $# -lt 1 ]
    then
        echo -e "Number of arguments: $#"
        return 1
    else
        echo -e "Number of arguments: $#"
        return 0
    fi
}

# No arguments given
given_args
echo -e "Function status code: $?\n"

# One argument given
given_args "argument"
echo -e "Function status code: $?\n"

# Pass the results of the function into a variable
content=$(given_args "argument")
echo -e "Content of the variable: \n\t$content"
```

#### Thực thi Return.sh (Return.sh - Execution)

```shellsession
phat2007dhsp@htb[/htb]$ ./Return.sh
Number of arguments: 0
Function status code: 1

Number of arguments: 1
Function status code: 0

Content of the variable: 
	Number of arguments: 1
```
